1. Executive Summary & Objective

The Campus Collaboration Hub demonstrates five fundamental networking protocols operating within a single distributed architecture. A critical technical challenge is establishing seamless cross-protocol communication between stateful stream sockets (TCP Chat) and stateless request-response architectures (HTTP REST API).

This document details the architectural design and code-level integration of three foundational requirements:

  • HistoryServer into Main.java: Background lifecycle management of the lightweight HTTP daemon on port 8080.
  • HistoryClient into the /history console command: Client-side execution of authenticated HTTP GET queries rather than direct RAM reads.
  • TCP chat messages into the shared MessageStore: Thread-safe in-memory message buffering acting as the cross-protocol producer-consumer bridge.
Core Integration Principle
Clients communicate exclusively via genuine network sockets (TCP port 5000 for chat, HTTP port 8080 for history). Server-side components communicate internally via the high-concurrency MessageStore singleton.

3. Component 1: HistoryServer into Main.java

3.1. Responsibility

Main.java functions as the server orchestrator. It instantiates the shared data repositories and launches each protocol server in its own non-blocking lifecycle thread. For the HTTP module:

  • It binds the com.sun.net.httpserver.HttpServer instance to Config.REST_HTTP_PORT (8080).
  • It registers REST contexts such as /messages.
  • It assigns an independent ExecutorService thread pool to prevent HTTP request saturation from impacting the TCP event loop.
  • It binds lifecycle termination to the JVM Shutdown Hook.

3.2. Integration Code in Main.java

package main;

import common.Config;
import common.MessageStore;
import http.HistoryServer;
import tcp.ChatServer;

public class Main {
    private static ChatServer chatServer;
    private static HistoryServer historyServer;

    public static void main(String[] args) {
        // 1. Initialize Shared In-Memory Storage
        MessageStore messageStore = MessageStore.getInstance();

        // 2. Start TCP Chat Server (Member 1 - Port 5000)
        chatServer = new ChatServer(Config.CHAT_TCP_PORT);
        Thread chatThread = new Thread(chatServer, "TCP-ChatServer-Thread");
        chatThread.start();

        // 3. Start HTTP History Server (Member 3 - Port 8080)
        historyServer = new HistoryServer(Config.REST_HTTP_PORT);
        historyServer.start();
        System.out.println("[Main] HTTP History REST Server started on port " + Config.REST_HTTP_PORT);

        // 4. Graceful Shutdown Management
        Runtime.getRuntime().addShutdownHook(new Thread(() -> {
            System.out.println("\n[Main] Shutdown signal detected. Stopping daemons...");
            if (chatServer != null) chatServer.stop();
            if (historyServer != null) historyServer.stop();
            System.out.println("[Main] All servers terminated cleanly.");
        }));
    }
}

4. Component 2: HistoryClient into the /history Command

4.1. Responsibility

When a user enters /history in the ConsoleClient, reading the local MessageStore directly only works in monolithic single-JVM testing. In actual network deployment, the client process runs on a separate machine. Thus, ConsoleClient must execute a genuine HTTP GET request via HistoryClient.

4.2. Implementation Blueprint (http/HistoryClient.java)

package http;

import common.Message;
import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;
import java.util.List;

public class HistoryClient {
    private final String endpoint;
    private final HttpClient client;

    public HistoryClient(String host, int port) {
        this.endpoint = "http://" + host + ":" + port + "/messages";
        this.client = HttpClient.newBuilder()
                .connectTimeout(Duration.ofSeconds(4))
                .build();
    }

    public List<Message> fetchHistory() throws IOException, InterruptedException {
        HttpRequest request = HttpRequest.newBuilder()
                .uri(URI.create(endpoint))
                .header("Accept", "application/json")
                .GET()
                .build();

        HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
        if (response.statusCode() == 200) {
            return parseMessages(response.body());
        }
        throw new IOException("HTTP error response: " + response.statusCode());
    }
}

5. Component 3: TCP Chat Messages into Shared MessageStore

5.1. The Producer-Consumer Bridge Pattern

TCP chat operates via persistent socket channels where messages arrive as line-delimited streams (MSG|<text>). In contrast, HTTP REST requests are stateless transactions. The Producer-Consumer Bridge pattern decouples these two communication models:

Role Component Protocol Action on MessageStore
Producer tcp.ClientHandler TCP (Port 5000) Appends incoming messages: addMessage(msg)
Consumer http.HistoryServer HTTP (Port 8080) Reads stored messages: getMessages() / toJsonArray()

5.2. Concurrency & Thread-Safety (CopyOnWriteArrayList)

In high-throughput environments, multiple client threads simultaneously append messages while HTTP handlers iterate over the collection to generate JSON responses. A standard ArrayList would trigger ConcurrentModificationException.

MessageStore resolves this through java.util.concurrent.CopyOnWriteArrayList:

  • Lock-free Iteration: Iterating through messages for HTTP serialization operates on an immutable snapshot, ensuring maximum read throughput without synchronization locks.
  • Atomic Writes: Append operations are thread-safe and isolated from active read operations.

6. Verification and Testing Runbook

Testing Procedure
Follow this sequence to demonstrate full cross-protocol integration during viva or grading evaluation.
  1. Start Server Host: 
    java -cp out Main
    Verify both console outputs: [Main] TCP Chat Server thread launched on port 5000 and [Main] HTTP History REST Server started on port 8080.
  2. Publish Chat Messages over TCP: Launch ConsoleClient, log in as Alice, and send: 
    /login Alice password123
Hello everyone! This is Alice on TCP.
  3. Query HTTP REST Endpoint (CLI): Execute an HTTP GET request using curl: 
    curl -s http://localhost:8080/messages
    Confirm the response contains Alice's message in JSON format.
  4. Retrieve History in ConsoleClient: Launch a second client as Bob and type: 
    /login Bob password123
/history
    Verify that Bob retrieves and displays Alice's TCP message via HTTP.
